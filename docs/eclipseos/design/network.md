# Network design

Status: proposed. The maintainer must accept this profile through the orchestrator before it becomes an implementation requirement.

## Atlas today

The networking tweak group runs the Atlas adapter-settings task and then writes three SMB/share values. The reset helper enumerates PCI network adapters and stores each matching class key in one variable; after enumeration, it changes a fixed list of advanced-property registry values to `0` only under the last matching class key, and only when each value is present. It then writes the SMB/share values: restrict anonymous access and enumeration, and disable SMB client bandwidth throttling. The calls have no build, edition or architecture guard. The LLMNR-disable task is present but commented out at the root call site. ## Lab evidence and limits

The 26H2 comparison includes `ame-drivers-network` in lane B, while lane A did not use ISO injection. The runs did not measure adapter throughput, packet loss, game latency, Wi-Fi behavior, network sleep/wake or share interoperability. The comparison therefore cannot attribute its Store/Xbox differences to network settings or establish a gaming benefit from adapter tuning. ([lab comparison](../lab/comparison.md))

Microsoft documents adapter advanced properties as driver-provided settings and explains that adapter offloads and interrupt moderation have workload-dependent trade-offs: some features reduce CPU work or improve throughput, while tuning interrupt moderation for throughput can hurt response time. Microsoft's SMB tuning guidance says the `DisableBandwidthThrottling=1` setting is for higher file-transfer throughput over high-latency links, is not optimal for every computer, and should be evaluated individually. These sources support preserving driver and OS defaults unless a specific workload is measured; they do not establish game-latency effects for Atlas's selected values. ([Microsoft: Network adapter performance](https://learn.microsoft.com/en-us/windows-hardware/drivers/network/performance-in-network-adapters); [Microsoft: File server performance tuning](https://learn.microsoft.com/en-us/windows-server/administration/performance-tuning/role/file-server/))

## Other playbook choices

The 26H2 playbook survey is a source inventory, not a matched network benchmark. Do not copy adapter or firewall choices from another playbook as evidence that they improve gaming, compatibility or privacy. ([26H2 playbook survey](../research/26h2-playbooks.md))

## Proposed EclipseOS default

1. **Keep Windows and vendor driver defaults for adapters.** Do not globally rewrite advanced NIC properties, disable power management, or force a latency profile. Keep built-in TCP/IP auto-tuning, offloads and interrupt moderation at their Windows/driver defaults. Expose any measured per-adapter profile as an optional, hardware-scoped choice that captures the original values and can restore them exactly. Microsoft's adapter documentation describes these settings as adapter properties that are configured on the individual device; performance guidance documents throughput/response-time trade-offs. ([Microsoft: Network adapter performance](https://learn.microsoft.com/en-us/windows-hardware/drivers/network/performance-in-network-adapters); [Microsoft: Set-NetAdapterAdvancedProperty](https://learn.microsoft.com/en-us/powershell/module/netadapter/set-netadapteradvancedproperty))
2. **Keep firewall and network profile behavior enabled.** Use Windows' detected network profile and firewall defaults. Do not set all connections to Private or disable firewall protections to reduce latency. Present file sharing as an explicit feature choice, with the active profile and allowed sharing behavior visible to the user.
3. **Use modern SMB protections, with a compatibility option for older peers.** Do not enable guest/anonymous access or legacy SMB globally. Keep anonymous share restrictions and current Windows SMB protections by default; offer a clearly scoped compatibility exception only for a named trusted peer or network, then restore the restriction automatically when removed. Check legacy NAS, printer and local file-sharing workflows before release. ([Microsoft: SMB features in Windows](https://learn.microsoft.com/en-us/windows-server/storage/file-server/smb-feature-descriptions?tabs=windows-server); [Atlas map: networking tweaks](../../map/tweaks-networking.md))
4. **Separate file-transfer tuning from gaming claims.** Keep `DisableBandwidthThrottling` at the Windows default unless a user has a demonstrated high-latency SMB transfer need; if offered, describe it as an SMB file-transfer option and test it independently. Do not present it as a general network latency or FPS optimization. ([Microsoft: File server performance tuning](https://learn.microsoft.com/en-us/windows-server/administration/performance-tuning/role/file-server/))
5. **Make every network change observable and reversible.** Record adapter identity, driver version, original property values, network profile, firewall state and SMB settings before a change. A restore action must reinstate the captured values without resetting unrelated protocols or removing devices. Keep DNS/multicast protocol changes disabled unless they have a tested privacy or compatibility rationale; test discovery, casting, local multiplayer and name resolution if such a change is proposed.

## Trade-offs and acceptance checks

Preserving Windows and driver defaults may retain power-saving or discovery behavior that some users prefer to adjust. It also avoids imposing one NIC vendor's tuning on unlike wired and wireless hardware. SMB hardening can block older anonymous-only peers; compatibility exceptions must be explicit and narrow. The current Atlas companion reset is not a precise rollback, so EclipseOS should not inherit it as the recovery mechanism.

Before implementation, test supported builds on representative wired and Wi-Fi adapters with current and older drivers. Compare defaults against any proposed profile using repeated idle and loaded latency, packet loss, throughput, CPU use, sleep/wake, reconnect and roaming checks; report hardware and driver versions and avoid inferring results from a single VM. Separately test Windows Update, Store downloads, Xbox app launch, Gaming Services presence, local multiplayer, discovery, SMB access to modern and legacy peers, and restore after reboot. Keep SMB throughput tests distinct from internet/game latency tests. The current lab contains no evidence for these network outcomes.
