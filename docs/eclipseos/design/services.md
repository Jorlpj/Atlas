# Services design

Status: proposed. The maintainer must accept this default through the orchestrator before it becomes an implementation requirement.

## Atlas today

Atlas `services.yml` saves Windows service and driver defaults, then disables selected services and drivers and runs file sharing, location and minimal indexing scripts. The entries include `InstallService` only in the observed lab hypothesis, not in the cited configuration list; configured startup value `4` is explicitly applied to `UCPD`, diagnostic services, `OneSyncSvc`, `TrkWks`, `PcaSvc`, `GpuEnergyDrv`, `NetBT` and `Telemetry`. The file has no build, edition or architecture conditions. ([Atlas map: services](../../map/services.md); `src/playbook/Configuration/atlas/services.yml:1-19`, `:25-75`)

The associated file-sharing script disables several network bindings, NetBIOS, discovery and sharing firewall rules, and changes the network profile to Public. Location and minimal indexing scripts change service state and Windows policies/settings; the indexing profile retains Start Menu programs and AtlasDesktop while excluding user folders. ([Atlas map: services](../../map/services.md); `src/playbook/Executables/AtlasModules/Scripts/ScriptWrappers/DisableFileSharing.ps1:7-33`; `src/playbook/Executables/AtlasDesktop/3. General Configuration/Location/Disable Location (default).cmd:1-40`; `src/playbook/Executables/AtlasDesktop/3. General Configuration/Search Indexing/Minimal Search Indexing (default).cmd:1-34`)

The generic restore utility offers saved Windows and Atlas service defaults, but the visible `(default)` helpers cover only a subset of the services Atlas changes. Upgrade revert does not restore service settings. ([Atlas map: services](../../map/services.md); `src/playbook/Executables/AtlasDesktop/9. Troubleshooting/Set services to defaults.cmd:23-54`; `src/playbook/Configuration/atlas/revert.yml:1-36`)

## Lab evidence and limits

In lane B, `InstallService` was observed Manual/Stopped after ISO injection and listed as a candidate that might relate to the Store/Xbox regression. This is a hypothesis only: the cause was not isolated. Lane B lacked Gaming Services after Windows Update reached zero pending updates; lane A retained the package after applying Atlas to an already serviced system. The runs differ in injection order and other conditions, so they do not prove a service caused the package failure. ([lab comparison](../lab/comparison.md); [lane B](../lab/lane-b.md); [problem catalog G18-G25](../research/problem-catalog.md))

Microsoft's Windows service guide identifies Microsoft Store, licensing, Update and Services Configuration as essential Windows services or capabilities. It states that disabling Windows License Manager or Software Protection Platform can prevent activation of Windows and Store apps, and that Windows Update also enables Store downloads and app updates. These are product-level dependencies, not proof that a particular service startup change caused the lane B outcome. ([Microsoft: Essential services and connected experiences](https://learn.microsoft.com/en-us/windows/privacy/essential-services-and-connected-experiences))

For search, Microsoft's current troubleshooting guidance recommends Windows Search running with Automatic (Delayed Start) when indexing is expected. It describes excluding folders or locations as ways to reduce indexed items and index size; disabling the service can leave search results incomplete. ([Microsoft: Troubleshoot Windows Search performance](https://learn.microsoft.com/en-us/troubleshoot/windows-client/shell-experience/windows-search-performance-issues))

## Proposed EclipseOS default

1. **Keep platform and servicing services at Windows defaults.** Do not disable Store, licensing, Windows Update, Services Configuration, or app installation services in the default profile. Microsoft documents Store and licensing functionality as depending on these capabilities. Keep Store readiness as a separate gate from the Windows Update pending-update count. ([Microsoft: Essential services and connected experiences](https://learn.microsoft.com/en-us/windows/privacy/essential-services-and-connected-experiences); [Windows Update design](windows-update.md))
2. **Avoid a global service-disable list.** Preserve Windows defaults unless a measured, specific need justifies a change. For any proposed service change, record its dependent features, exact startup change, device/build scope, and a tested restore path. Keep privacy choices at the feature or policy level where possible rather than silently removing a shared service.
3. **Make file sharing an explicit, reversible choice.** Default to Windows network profile and firewall behavior. If offering a hardening option, disclose that it changes adapter bindings, NetBIOS, discovery, SMB-related sharing and the network profile; provide one restore action and test private and public network use. ([Atlas map: services](../../map/services.md))
4. **Use scoped indexing controls.** Keep Windows Search available for users who want indexed search. Offer a reduced index scope through supported Windows Search settings and explain which folders are excluded; do not disable `WSearch` as a gaming optimization by default. Let Windows' own idle, battery and activity behavior manage indexing, then measure resource use on representative machines. ([Microsoft: Troubleshoot Windows Search performance](https://learn.microsoft.com/en-us/troubleshoot/windows-client/shell-experience/windows-search-performance-issues))
5. **Treat optional services as per-feature decisions.** Location, Bluetooth, printing, network discovery, and device or vendor services vary by hardware and use. Keep them available by default or expose clear opt-ins with exact feature impact and an immediate restore path. Do not infer that a service is unused from one clean VM.
6. **Capture and verify service state.** Before changes, save exact service and driver startup states. After changes and after reboot, verify Store app installation/update, Xbox and Gaming Services presence, Windows Update scan/install, network sharing, location choice, search, and any enabled peripherals. A successful Windows Update scan alone does not verify Store servicing.

## Trade-offs and acceptance checks

Keeping optional services available can retain background activity and some indexed content; narrowing indexing or disabling a feature may reduce that work but can remove search results, sharing, or device functionality. The default favors compatibility and reversibility; performance changes need a matched measurement on supported builds and representative hardware.

For every supported build and install path, record startup and running state for services changed by EclipseOS before and after reboot, including `InstallService`, Windows Search, Store/licensing-related services, and `UCPD`. Test a Store app install and update, Xbox app launch, Gaming Services presence, and a Windows Update scan/install after the required servicing gate. Test file sharing and search under their enabled and disabled choices, restore from the saved state, and repeat after reboot. Include a device with Bluetooth and printing hardware before making any claim about optional service savings. Do not report service counts alone as evidence of lower latency or improved game performance.
