# AtlasDesktop

`custom.yml` replaces `%WINDIR%\AtlasDesktop` on upgrades and copies the AtlasDesktop tree into `%WINDIR%` during setup. Its contents are user-launched shortcuts and command files, not a single automatic sequence. Many paired controls write an `HKLM\SOFTWARE\AtlasOS\Services\<name>` state and path so Atlas can show or restore a toggle; that metadata does not itself revert the setting. Commands request elevation or call `RunAsTI.cmd` where required. (`src/playbook/Configuration/custom.yml:11-44`; `src/playbook/Executables/AtlasDesktop/3. General Configuration/Automatic Updates/Disable Automatic Updates (default).cmd:2-18`; `src/playbook/Executables/AtlasDesktop/7. Security/Defender/Toggle Defender.cmd:2-15`)

The tree also contains `.url` links and paired `Enable`/`Disable` or `default` controls; filenames indicate the intended counterpart, but each script's effects must be read individually. There is no AtlasDesktop-wide undo routine: controls may write registry values, remove AppX packages, alter boot configuration, or reset drivers/network state. Copilot's enable counterpart has an AppX-install path: when `IsCopilotAvailable` is 0, it calls `winget install` for Copilot; otherwise it restores the taskbar button. The Microsoft Store enable command only registers the manifest at an existing package location, so its source does not show a download or provision operation when the package is absent. Explorer and boot controls explicitly reverse their selected values. (`src/playbook/Executables/AtlasDesktop/3. ## Update and Store/Xbox scope

Some controls change Windows Update policy: the automatic-updates toggle sets `AUOptions=2`, and the driver `.reg` files set `ExcludeWUDriversInQualityUpdate` and driver-search values. Store/Xbox-sensitive controls include: FSO/Game Bar disable removes the `xboxgamingoverlay` AppX, and its enable counterpart runs `winget install 9NZKPSTSNW4P`; Store App Archiving writes `AllowAutomaticAppArchiving=0` or `1`; and the Microsoft Store pair removes the Store package for all users, then attempts to register its manifest from an existing install location. Copilot disable removes the Copilot AppX; its enable counterpart installs Copilot through `winget` on the `IsCopilotAvailable=0` branch. These are user-launched operations, not proof of behavior during the root playbook sequence. (`src/playbook/Executables/AtlasDesktop/3.
