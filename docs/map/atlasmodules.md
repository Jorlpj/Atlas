# AtlasModules

`custom.yml` copies `Executables/AtlasModules` recursively into `%WINDIR%\AtlasModules` for the playbook run. On upgrades it first stops processes and tasks using the old Atlas folders, then deletes those folders; the copy step halts the run on a missing source folder or failed copy. No architecture or build gate is attached to this copy. (`src/playbook/Configuration/custom.yml:11-44`; `src/playbook/Executables/STOPFOLDERPROC.ps1:16-17,45-46,112-113`)

`initPowerShell.ps1` adds `%WINDIR%\AtlasModules\Scripts\Modules` to the current PowerShell process's `PSModulePath`, making its modules importable by callers. This is process-local setup; the root copy itself installs the files under Windows. (`src/playbook/Executables/AtlasModules/initPowerShell.ps1:1-4`)

## Included PowerShell modules

These modules expose reusable functions. Their presence in the copied tree does not itself run their optimizations; task files or interactive scripts call them. The configured bulk calls and task conditions are mapped in [the tweak group pages](tweaks-index.md) and [the Scripts group](tweaks-scripts.md).

| Module | Effects when its exported bulk function is called |
| --- | --- |
| `Debloat` | Changes current-user Content Delivery Manager and Storage Sense values, starts Disk Cleanup's `SilentCleanup` task, disables reserved storage through DISM, and disables three scheduled tasks (PcaPatchDbTask, UCPD velocity, UsageDataReporting). (`src/playbook/Executables/AtlasModules/Scripts/Modules/Debloat/Debloat.psm1:1-74`) |
| `Performance` | Changes NTFS last-access behavior, Explorer folder discovery, background-app policy, Game Bar capture settings and power-throttling registry values, and disables the SleepStudy task. (`src/playbook/Executables/AtlasModules/Scripts/Modules/Performance/Performance.psm1:2-70`) |
| `Privacy` | Writes current-user and machine registry values for advertising ID, sync-provider notifications, telemetry, device setup suggestions, input and speech, Recall, tailored experiences, error reporting, search privacy and user-activity upload; it also sets Windows Media Player privacy. (`src/playbook/Executables/AtlasModules/Scripts/Modules/Privacy/Privacy.psm1:2-136`) |
| `Qol` | Changes Explorer, Start, taskbar, personalization, accessibility, shell and input registry/settings; includes `Disable-AutomaticStoreAppArchiving`, which changes Store app archiving behavior. (`src/playbook/Executables/AtlasModules/Scripts/Modules/Qol/Qol.psm1:4-452,453-520`) |
| `Miscellaneous` | Adds Music and Videos locations to Explorer Home, configures time servers, and resets performance counters. (`src/playbook/Executables/AtlasModules/Scripts/Modules/Miscellaneous/Miscellaneous.psm1:2-42`) |
| `Scripts` | Backs up service start values, updates Client CBS state, changes VBS/core isolation and device settings, configures file associations and mitigations, optimizes PowerShell startup, sets profile pictures and power settings. (`src/playbook/Executables/AtlasModules/Scripts/Modules/Scripts/Scripts.psm1:7-245`) |
| `Themes` | Applies a theme, updates the theme MRU registry value on builds 22000+, and sets a lock-screen image. (`src/playbook/Executables/AtlasModules/Scripts/Modules/Themes/Themes.psm1:1-5,7-94,96-142`) |
| `Shortcuts`, `AllRegistryUsers`, `UserPaths`, `Utils` | Provide shortcut creation; enumerate loaded user registry hives; resolve Windows known-folder and system-drive paths; and display prompts or stop processes/tasks below specified roots. Their effects therefore describe callable module behavior; they do not establish that the corresponding bulk function runs in the root playbook sequence. There are direct YAML actions for related settings, mapped in the tweak pages. The Qol module's Store app-archiving function invokes the matching AtlasDesktop command when called. ## Scripts, packages and interactive tools

- `packageInstall.ps1` is an elevated servicing helper: it can remove online Windows packages, add CABs from `%WINDIR%\AtlasModules\Packages`, and create a WinSxS repair-source directory plus a servicing-policy `LocalSourcePath`. Its package architecture selection is runtime-driven. The playbook's Defender and telemetry tasks call it for the corresponding CABs; see [components](components.md) for their option paths. (`src/playbook/Executables/AtlasModules/Scripts/packageInstall.ps1:1-30,164-219,292-367`; `src/playbook/Configuration/atlas/components.yml:36-61`)
- `newUsers.ps1` performs setup when invoked by the default-user RunOnce task: on builds 22000+, it calls the old-context-menu and Gallery commands and sets the Atlas theme/MRU; it also sets the lock-screen image, applies network-pane, folder-discovery and visual-effect commands, sets taskbar pins from the `Browser` setup option, changes `SearchboxTaskbarMode`, and logs off. (`src/playbook/Configuration/tweaks/misc/add-newUser-script.yml:5-10`; `src/playbook/Executables/AtlasModules/Scripts/newUsers.ps1:23-56`)
- `UpdateDrivers.ps1` installs/imports the PSWindowsUpdate module, enables Microsoft Update, presents available driver updates for selection and installs selected drivers; it is an interactive toolbox action, not a root-sequence action. (`src/playbook/Executables/AtlasModules/Scripts/ScriptWrappers/UpdateDrivers.ps1:19-35,86-120`; `src/playbook/Executables/AtlasDesktop/2. Drivers/Run Update Drivers.cmd:2-21`)
- `RemoveEdge.ps1` supports Edge uninstall/reinstall and WebView2 install, with switches controlling Edge user-data removal, AppX handling and prompts. In the configured component task it is called with `-KeepAppX` while AME handles the AppX removal; details are in [components](components.md). (`src/playbook/Executables/AtlasModules/Scripts/ScriptWrappers/RemoveEdge.ps1:3-38`; `src/playbook/Configuration/atlas/components.yml:17-29`)
- Other wrappers provide power, VBS, Defender and telemetry controls, software installation, Send To context-menu changes and Toolbox setup. Their effects depend on launching those wrappers or the calling task. The Toolbox installer downloads the latest Atlas Toolbox setup executable and starts it in silent-install mode, adding the desktop-icon task. (`src/playbook/Executables/AtlasModules/Scripts/ScriptWrappers/DisablePowerSaving.ps1:1-110`; `src/playbook/Executables/AtlasModules/Scripts/ScriptWrappers/ConfigVBS.ps1:1-38`; `src/playbook/Executables/AtlasModules/Scripts/ScriptWrappers/ToggleDefender.ps1:17-85`; `src/playbook/Executables/AtlasModules/Scripts/ScriptWrappers/TelemetryComponents.ps1:17-92`; `src/playbook/Executables/AtlasModules/Scripts/installToolbox.ps1:1-31`)

`Tools` contains `multichoice.exe` and `SetTimerResolution.exe`, and `Other` includes XML, layout and icon assets. The bundled README records hashes, source repositories and last-verification dates for those binaries; its listed verification dates are 2024. (`src/playbook/Executables/AtlasModules/README.md:1-29`)

## Revert and servicing scope

The root upgrade path replaces the AtlasModules tree after stopping its known processes and tasks. There is no matching general undo for registry, package-servicing, task, or user-profile changes exposed by the modules; individual configured actions and backups are covered in their area pages. The service backup helper writes `atlasServices.reg`; package servicing may add/remove CBS packages and configure a repair source. (`src/playbook/Configuration/custom.yml:11-44`; `src/playbook/Executables/AtlasModules/Scripts/Modules/Scripts/Scripts.psm1:7-29`; `src/playbook/Executables/AtlasModules/Scripts/packageInstall.ps1:164-219,292-367`)

Store/AppX and Windows servicing touchpoints here are Store app archiving in the QoL module and online CAB/package servicing in `packageInstall.ps1`. No Xbox package action appears in the module call summaries above. Driver installation is a separate user-launched Microsoft Update path. (`src/playbook/Executables/AtlasModules/Scripts/Modules/Qol/Qol.psm1:368-370`; `src/playbook/Executables/AtlasModules/Scripts/packageInstall.ps1:164-219,292-320`; `src/playbook/Executables/AtlasModules/Scripts/ScriptWrappers/UpdateDrivers.ps1:31-35,86-120`)
