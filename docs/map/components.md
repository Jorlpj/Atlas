# Components

`components.yml` is not rerun during an upgrade (`onUpgrade: false`). It contains unconditional startup and Smart App Control registry changes, Edge removal behind `uninstall-edge`, OneDrive cleanup, and option-gated Defender/telemetry package changes. Its only explicit ISO-only action deletes the offline `WdBoot` service key. (`src/playbook/Configuration/atlas/components.yml:1-5`, `:6-15`, `:17-61`)

## Actions and conditions

- Deletes the `SecurityHealth` value from the machine Run key and writes DWORD `0` to `HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy\VerifiedAndReputablePolicyState`. No option, build, edition, or architecture condition is specified for these actions. (`src/playbook/Configuration/atlas/components.yml:6-15`)
- With `uninstall-edge`, calls `RemoveEdge.ps1` elevated for the current user with `-UninstallEdge -RemoveEdgeData -KeepAppX -NonInteractive`, then removes the `Microsoft.MicrosoftEdge` AppX family and adds two Edge package names to `AppxAllUserStore\Deprovisioned`. The configuration comments that script-side AppX removal seems to fail, so AME Wizard handles it, and that recent Windows builds may already lack this AppX. (`src/playbook/Configuration/atlas/components.yml:17-29`) The wrapper's uninstall path downloads and runs `Remove-Edge.exe`; its data-removal path deletes the current user's local Edge data directory. (`src/playbook/Executables/AtlasModules/Scripts/ScriptWrappers/RemoveEdge.ps1:349-380`)
- Runs `ONED.cmd` without an option condition. The script exits early if it finds non-empty OneDrive folders in a user profile; otherwise it stops OneDrive, runs either system OneDrive setup uninstaller if present, removes OneDrive data folders and shortcuts, deletes matching SyncRootManager registry keys and scheduled tasks, and edits per-user OneDrive-related registry entries. (`src/playbook/Configuration/atlas/components.yml:31-34`; `src/playbook/Executables/ONED.cmd:3-19`, `:22-43`, `:47-66`)
- With `defender-disable`, deletes `HKLM\OfflineSys\ControlSet001\Services\WdBoot` only for ISO setup, then asks `packageInstall.ps1` to install matching NoDefender and NoTelemetry CABs. With `defender-enable`, it installs NoTelemetry and uninstalls NoDefender. The package utility removes installed Windows packages and adds matching CAB packages from its package directory. (`src/playbook/Configuration/atlas/components.yml:36-61`; `src/playbook/Executables/AtlasModules/Scripts/packageInstall.ps1:6-12`, `:164-197`, `:203-219`, `:292-320`)

The configuration supplies no separate build, edition, or architecture conditions for these actions; the Edge comments identify differing presence on updated versus non-updated Windows builds. The package utility chooses its package architecture from the system at runtime. (`src/playbook/Configuration/atlas/components.yml:17-29`, `:36-61`; `src/playbook/Executables/AtlasModules/Scripts/packageInstall.ps1:29-30`)

## Restore coverage and servicing scope

`defender-enable` is an explicit configuration path that removes the NoDefender package. The package UI scripts also expose install and uninstall actions for Defender and NoTelemetry packages, but this does not establish a general automatic rollback for all component actions. (`src/playbook/Configuration/atlas/components.yml:43-61`; `src/playbook/Executables/AtlasModules/Scripts/ScriptWrappers/ToggleDefender.ps1:17-24`, `:67-85`; `src/playbook/Executables/AtlasModules/Scripts/ScriptWrappers/TelemetryComponents.ps1:21-28`, `:74-92`)

The upgrade revert file is `onUpgrade: true` but only deletes legacy Explorer `ThisPCPolicy` values; it has no Edge, OneDrive, SecurityHealth, Smart App Control, Defender, telemetry-package, or `WdBoot` restore action. (`src/playbook/Configuration/atlas/revert.yml:1-36`) Edge actions explicitly affect AppX servicing by removing an AppX family and adding deprovisioned package keys. This file contains no direct Store or Xbox action; the citations alone do not establish runtime impact to Store or Xbox. (`src/playbook/Configuration/atlas/components.yml:25-29`)
