# Top-level executable scripts

This page maps text scripts and configuration assets directly under `src/playbook/Executables/`. It follows the configuration call sites; the nested `AtlasModules/` and `AtlasDesktop/` trees have separate map pages or area pages. `custom.yml` runs several helpers around the main tasks, then calls the Atlas task files in sequence. (`src/playbook/Configuration/custom.yml:5-16,27-44,46-80,83-112`)

## Deployment helpers

- `STOPFOLDERPROC.ps1` finds processes whose executable paths are under `%WINDIR%\AtlasModules` or `%WINDIR%\AtlasDesktop`, stops matching scheduled tasks, ends the named Force Timer Resolution task, and checks whether `SetTimerResolution.exe` is still locked. It runs on upgrades before the old folders are deleted. (`src/playbook/Executables/STOPFOLDERPROC.ps1:1-14,16-43,45-113,115-125`; `src/playbook/Configuration/custom.yml:10-16`)
- `DISABLENOTIFS.cmd` denies the current user's notification-listener consent, disables notification sounds, toast notifications, cloud notifications, Notification Center, and the Wpn services; it hides two Settings pages. The root task invokes it during deployment. (`src/playbook/Executables/DISABLENOTIFS.cmd:3-28`; `src/playbook/Configuration/custom.yml:46-51`)
- `CLEANUP.ps1` configures and runs Disk Cleanup preset 64 only when no other Windows installation is found on another filesystem drive, clears the first available user temp directory and the system temp directory, then deletes all VSS shadows. The root task runs it elevated during deployment. (`src/playbook/Executables/CLEANUP.ps1:2-47,49-64,66-104`; `src/playbook/Configuration/custom.yml:62-68`)
- `APPLYDUHIVE.ps1` reads tweak YAML paths, selects HKCU paths, and copies values present in the current user hive into the loaded `AME_UserHive_Default` hive. The root task calls it after the main tasks while that hive was loaded earlier in the sequence. (`src/playbook/Executables/APPLYDUHIVE.ps1:1-42`; `src/playbook/Configuration/custom.yml:5-9,74-89`)
- `SETPATHS.ps1` elevates if needed and rewrites each `path` value below `HKLM\SOFTWARE\AtlasOS\Services` so the path points beneath the current Windows `AtlasDesktop` folder. The root task runs it after the main tasks and before unloading the default-user hive. (`src/playbook/Executables/SETPATHS.ps1:1-22`; `src/playbook/Configuration/custom.yml:91-103`)

## Atlas folder defaults and service backups

`DEFAULT.reg` seeds `HKLM\SOFTWARE\AtlasOS\Services` state and script-path entries for AtlasDesktop controls. For example, it registers App Store archiving, Automatic Updates, and several other controls with a `state` value and a default-script `path`. The default task imports this file, then runs `DEFAULT.ps1` on upgrades; that script elevates and starts matching AtlasDesktop scripts with `/silent /noAction`. (`src/playbook/Executables/DEFAULT.reg:3-27,49-55`; `src/playbook/Executables/DEFAULT.ps1:1-16`; `src/playbook/Configuration/atlas/default.yml:5-15`)

`BACKUP.ps1` exports service configuration values to a `.reg` file unless the destination already exists; service entries whose description matches Windows Defender are excluded. The services task saves a Windows-service backup, and a scripts tweak saves a second Atlas service backup. This is a backup operation, not a general rollback for every playbook change. (`src/playbook/Executables/BACKUP.ps1:1-23`; `src/playbook/Configuration/atlas/services.yml:14-19`; `src/playbook/Configuration/tweaks/scripts/script-backup2.yml:1-9`)

## Components and configuration support

- `ONED.cmd` first exits if any user's OneDrive folder contains files. Otherwise it stops OneDrive, calls the Windows uninstallers, removes OneDrive directories and shortcuts, deletes per-user OneDrive scheduled tasks and registry values, and removes Explorer namespace pins. It is called by `components.yml` without an option condition. (`src/playbook/Executables/ONED.cmd:3-10,12-20,22-66`; `src/playbook/Configuration/atlas/components.yml:31-35`)
- `DISABLEPNP.ps1` disables present Plug and Play devices whose friendly names match its fixed 21-name list (including selected chipset, timer, and system devices); unmatched devices are left alone, and errors are ignored. The script tweak calls it from the configured `script-devices` task. (`src/playbook/Executables/DISABLEPNP.ps1:1-27`; `src/playbook/Configuration/tweaks/scripts/script-devices.yml:1-9`)
- `CLIENTCBS.ps1` searches the Accounts Settings extension JSON for feature IDs, chooses the matching ViVeTool archive for ARM64 versus other architectures, hides the account Settings page, and disables the discovered feature IDs for the next reboot. It exits if those files or IDs are absent. The script tweak is the caller. (`src/playbook/Executables/CLIENTCBS.ps1:9-17,19-48,50-84`; `src/playbook/Configuration/tweaks/scripts/script-clientcbs.yml:1-8`)
- `NGEN.ps1` adds the .NET runtime directory to PATH and runs `ngen install` on assemblies already loaded in its PowerShell domain. The root sequence calls its tweak task while optimizing PowerShell. (`src/playbook/Executables/NGEN.ps1:1-6`; `src/playbook/Configuration/custom.yml:56-60`; `src/playbook/Configuration/tweaks/scripts/script-ngen.yml:1-8`)

## Shell, profile and notification helpers

- `ENABLENOTIFS.cmd` reverses several notification settings made by `DISABLENOTIFS.cmd`: it allows notification consent and sounds, enables toast notifications, removes the cloud-notification policy, unhides the two Settings pages, and restarts the notification services with automatic startup. It is called by the notifications enable task. (`src/playbook/Executables/ENABLENOTIFS.cmd:1-22`; `src/playbook/Executables/DISABLENOTIFS.cmd:3-28`; `src/playbook/Configuration/tweaks/misc/enable-notifications.yml:1-9`)
- `PFP.ps1` resizes `user.png` into the listed account-picture dimensions and writes the resulting `user` and `guest` image files under the common account-picture directory. Its caller is the profile-picture tweak. (`src/playbook/Executables/PFP.ps1:1-23`; `src/playbook/Configuration/tweaks/scripts/script-pfp.yml:1-9`)
- `SHORTCUTS.ps1` copies the configured default shortcut to each loaded user's Desktop when that folder exists, and also copies it into the common Start Menu Programs folder. The caller is the shortcut-creation tweak. (`src/playbook/Executables/SHORTCUTS.ps1:1-27`; `src/playbook/Configuration/tweaks/misc/create-shortcuts.yml:1-8`)
- `STARTMENU.ps1` copies `Layout.xml` into each discovered user's Start Menu data folder; for non-default users, it removes Start Menu cache files and tile-grid registry entries, then removes the Start `Config` value. The QoL task invokes it. (`src/playbook/Executables/STARTMENU.ps1:1-44`; `src/playbook/Executables/Layout.xml:1-11`; `src/playbook/Configuration/tweaks/qol/config-start-menu.yml:1-20`)
- `TASKBARPINS.ps1` recreates taskbar shortcut data and binary taskbar registry values for each loaded user. Its optional browser argument selects Brave, Firefox, LibreWolf or Chrome; without one it chooses Edge when available and otherwise File Explorer. `SETTABST.ps1` registers a scheduled task with an AtLogon trigger to run the Atlas taskbar pin script, using separate task names for default and named browser configuration; it does not register an unlock trigger. The QoL configuration selects the calls. (`src/playbook/Executables/TASKBARPINS.ps1:1-115`; `src/playbook/Executables/SETTABST.ps1:1-24`; `src/playbook/Configuration/tweaks/qol/taskbar/config-pins.yml:45-78`)

## Software installation and associations

`SOFTWARE.ps1` accepts switches for Toolbox and optional Brave, Firefox or Chrome installers. With no such switch, its utility path installs Visual C++ and DirectX runtimes and selects NanaZip or 7-Zip; NanaZip is added as a provisioned AppX package, with a 7-Zip fallback path. It uses temporary downloads and removes its temporary folder on the normal completion paths. `start.yml` calls the utility path, Toolbox switch and browser switch selected by configuration. These installer actions are not paired with uninstall steps in the mapped revert task. (`src/playbook/Executables/SOFTWARE.ps1:1-36,39-91,93-149,152-233`; `src/playbook/Configuration/atlas/start.yml:41-93`; `src/playbook/Configuration/atlas/revert.yml:1-36`)

`LIBREWOLF.ps1` downloads and silently installs LibreWolf, then installs its updater, creates a scheduled updater task per enabled user, and adds shortcuts. The browser choice in `start.yml` selects this script. This page records the configured AppX-provisioning call in `SOFTWARE.ps1`; it does not establish runtime effects on Store or Xbox. (`src/playbook/Executables/LIBREWOLF.ps1:6-67`; `src/playbook/Configuration/atlas/start.yml:76-82`; `src/playbook/Executables/SOFTWARE.ps1:166-188`)

`FILEASSOC.cmd` iterates user hives and applies file-class registrations for 7-Zip associations; it invokes `ASSOC.ps1` for the configured per-user association work. `ASSOC.ps1` computes the Windows UserChoice hash and writes URL and extension association state, including the application-association toast suppression values. The file-association tweak task selects the batch file and the applications to process. (`src/playbook/Executables/FILEASSOC.cmd:1-68,69-530`; `src/playbook/Executables/ASSOC.ps1:1-3,52-59,145-189,191-267`; `src/playbook/Configuration/tweaks/scripts/script-file-associations.yml:1-28`)

## Revert and servicing scope

Some helpers have paired user-facing enable/default controls, including notifications and the AtlasDesktop controls represented by `DEFAULT.reg`. The upgrade-time `revert.yml` action list does not reverse temp cleanup, VSS deletion, OneDrive removal, NGEN installation, browser/software installs, or the root user-association writes. Revert coverage for other actions depends on their individual AtlasDesktop or tweak controls; a default or backup file is not evidence of a complete rollback. (`src/playbook/Configuration/atlas/revert.yml:1-36`; `src/playbook/Executables/CLEANUP.ps1:66-104`; `src/playbook/Executables/ONED.cmd:12-66`; `src/playbook/Executables/NGEN.ps1:1-6`; `src/playbook/Executables/FILEASSOC.cmd:54-68`; `src/playbook/Executables/ENABLENOTIFS.cmd:1-22`; `src/playbook/Executables/DEFAULT.reg:3-27`)

AppX servicing is directly touched by the NanaZip provisioning branch. The other scripts described here do not directly call Store or Xbox operations; this source inspection alone does not prove compatibility outcomes. (`src/playbook/Executables/SOFTWARE.ps1:166-188`)
